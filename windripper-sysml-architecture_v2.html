System Overview

Windripper is a container image webhook processing system that monitors Harbor registry push events, extracts container metadata and configuration, persists it to a PostgreSQL database, and notifies downstream systems (Windstorm) of new container commits.

Key Capabilities

  • Receives and processes Harbor webhook events for artifact pushes
  • Queries Harbor API to retrieve container manifests and configurations
  • Extracts platform-specific (linux/amd64) container metadata
  • Persists container and commit information to PostgreSQL database
  • Notifies downstream webhook endpoints (Windstorm) upon successful processing
  • Deployed as ephemeral Kubernetes pods triggered by Argo Events

Technology Stack

Key Functions

1. Webhook Reception

  • Receives Harbor PUSH_ARTIFACT events
  • Validates event type
  • Extracts event parameters

2. Resource Parsing

  • Parses resource_url format
  • Extracts host, project, image, tag
  • Removes 'sha256:' prefix from digest

3. Harbor API Interaction

  • Queries multi-platform manifest
  • Selects linux/amd64 child digest
  • Fetches platform-specific config
  • Extracts Cmd and WorkingDir

4. Database Persistence

  • Checks for existing container records
  • Inserts new containers if needed
  • Creates container_commits entries
  • Updates project/image IDs

High Availability Considerations

Stateless Design: Windripper pods are ephemeral and stateless, making horizontal scaling straightforward. Each webhook event creates a new pod that processes independently.
  • Event Source HA: Argo Events can be configured with multiple replicas
  • Database HA: PostgreSQL can use replication or managed cloud services
  • Pod Failures: Failed pods are logged; Harbor can retry webhooks
  • Concurrent Processing: Multiple events trigger multiple pods simultaneously
  • Resource Limits: Kubernetes namespace quotas prevent resource exhaustion

Data Model

Entity-Relationship Diagram

Table: containers

Column Type Constraints Description
id INTEGER PRIMARY KEY, AUTO_INCREMENT Unique container identifier
resource_url VARCHAR(255) NOT NULL Full resource path (host/project/repo:tag)
host VARCHAR(255) NOT NULL Registry hostname
project VARCHAR(255) NOT NULL Harbor project name
project_id INTEGER NULLABLE Harbor numeric project ID
image VARCHAR(255) NOT NULL Repository/image name
image_id INTEGER NULLABLE Harbor numeric repository ID
tag VARCHAR(255) NOT NULL Image tag (e.g., 'latest', 'v1.0.0')

Table: container_commits

Column Type Constraints Description
id INTEGER PRIMARY KEY, AUTO_INCREMENT Unique commit identifier
containers_id INTEGER FOREIGN KEY → containers(id) Reference to parent container
digest VARCHAR(64) NOT NULL SHA256 digest (without 'sha256:' prefix)
cmd TEXT NOT NULL JSON-serialized command array from config
working_dir VARCHAR(255) NOT NULL Container working directory
date TIMESTAMP NOT NULL, DEFAULT NOW() Timestamp when commit was recorded

Data Operations

Container Insert/Lookup

  1. Query by (project, image, tag)
  2. If not found, INSERT new container
  3. Retrieve container ID for commits
  4. Update project_id/image_id if NULL

Commit Creation

  1. Extract digest from webhook
  2. Query Harbor for config
  3. Serialize Cmd to JSON
  4. INSERT with current timestamp

Example Data Flow

# Input Webhook Event { "type": "PUSH_ARTIFACT", "event_data": { "resources": [{ "resource_url": "harbor.example.com/production/myapp:v1.2.3", "digest": "sha256:abc123def456..." }] } } # Parsed Components host = "harbor.example.com" project = "production" image = "myapp" tag = "v1.2.3" digest = "abc123def456..." # Container Query/Insert SELECT * FROM containers WHERE project='production' AND image='myapp' AND tag='v1.2.3' -- If not found: INSERT INTO containers (resource_url, host, project, image, tag) VALUES ('harbor.example.com/production/myapp:v1.2.3', 'harbor.example.com', 'production', 'myapp', 'v1.2.3') # Harbor API Response (simplified) { "extra_attrs": { "config": { "Cmd": ["/bin/sh", "-c", "python app.py"], "WorkingDir": "/app" } }, "project_id": 42, "repository_id": 123 } # Commit Insert INSERT INTO container_commits (containers_id, digest, cmd, working_dir, date) VALUES (1, 'abc123def456...', '["/bin/sh", "-c", "python app.py"]', '/app', '2026-02-01 16:30:00') # Container Update (if IDs were NULL) UPDATE containers SET project_id=42, image_id=123 WHERE id=1 # Windstorm Notification POST http://windstorm-webhook-eventsource-svc:12000/windstorm { "source": "ripper", "payload": { "container_id": 1 } }
